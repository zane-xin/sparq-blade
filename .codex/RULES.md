# Engine Code Style

本文档约束 `blade` 的注释规范与测试命名规范。

## 1. 注释规范

### 1.1 适用范围

以下内容默认必须补标准注释：

- 所有导出的 `function`
- 所有导出的 `interface`
- 所有导出的对象类型 `struct`
- 所有公开协议相关字段
- 语义不直观的内部辅助函数

以下内容可以不写：

- 含义极其直接的局部变量
- 单行即可看懂的私有实现细节
- 仅做字面量转发的简单包装

### 1.2 注释语言

统一使用中文。

要求：

- 说明“这个东西的职责是什么”
- 说明“字段或参数代表什么语义”
- 说明“何时使用、由谁消费”

不要求：

- 逐字翻译代码名
- 写作者、邮箱、日期
- 写无信息量注释，例如“给变量赋值”

### 1.3 函数注释格式

导出函数默认使用块注释：

```go
/**
 * CompileReactions
 * 根据 reaction 规则编译依赖图。
 * 仅负责静态编译，不执行运行时调度。
 * @param rules reaction 规则列表。
 * @param options 编译选项，主要用于注入可用资源清单。
 * @returns 编译结果与结构化错误列表。
 */
func CompileReactions(...) {}
```

约束：

- 第一行写职责总结
- 有副作用时要写清副作用
- 参数语义复杂时补 `@param`
- 返回值语义不直观时补 `@returns`
- 抛错条件明显时补充说明

### 1.4 接口与类型注释格式

接口、对象类型、公开协议字段必须写中文注释。

推荐写法：

```go
struct RuntimeContext {
    /** 当前 runtime 对应的节点对象。 */
    node BasicNode
    /** 供 renderer bridge 消费的 props。 */
    props Props
    /** 当前节点所属 scene。 */
    scene string
}
```

约束：

- 字段逐项写注释，不省略关键字段
- 注释描述“语义”和“消费方”，不要只描述“类型”
- 内部字段要明确标注“仅内部使用”
- 协议字段要明确标注“公开”或“运行时”
